这里是基于我自己的博客构建经历编辑的部署教程，本地部署和主题配置详情见 Hugo 和 stack 主题官方网站。如果对于本地自动化推送之前的步骤有疑问请参考官方文档。

本地初始化Hugo

本地初始化主要分为三步，创建hugo博客项目，安装主题，本地运行。

前提条件

需要提前安装好 Hugo 和 Git。对于部分 Windows，需要安装好 power shell。

📝 Note

power shell 和 Windows power shell，cmd是不同的。你可以在Windows自带的商店中下载到power shell，相关命令为pwsh。

💡 Tip

对于 Windows，Hugo可以使用 winget 进行安装，这样可以自动配置好环境变量并且有利于自动更新程序。

# quickstart 可以换为绝对路径。如果是使用winget等方式部署的hugo，推荐填写绝对路径，以免不知道项目的位置。
# --format yaml 为可选项。hugo支持yaml 和 toml 格式的配置文件。而且并不是你在这里选定了一种格式就无法使用另一种格式了。
# 它只影响项目生产时的默认配置文件格式。
hugo new site quickstart --format yaml

# 进入项目文件夹
cd quickstart

# 初始化 git
git init

# 将需要的主题作为 git 子模块加入到项目中。
# 我使用的是 stack 主题，命令如下：
# git submodule add https://github.com/CaiJimmy/hugo-theme-stack/ themes/hugo-theme-stack
git submodule add https://github.com/theNewDynamic/gohugo-theme-ananke.git themes/ananke

# 将你下载的主题选作为使用主题
# 如果你之前选择了 yaml 格式，这里命令就要改成：
# echo "theme: ananke" >> hugo.yaml
echo "theme = 'ananke'" >> hugo.toml

# 社会启动 hugo，在你的本地生成一个静态页面博客，如果没有报错就表明没有问题，项目初始化完成，ctrl + c 关闭即可。
# 页面没有元素属于正常现象，出现页面错误请按照官方文档自行排查
hugo server

主题

完成上面的步骤后，页面的情况大概率是什么都没有的。现在，进入下载好的 stack 主题文件夹下的 demo 文件夹（themes\hugo-theme-stack\demo）。 里面是需要的模板文件，将其复制到根目录对应的文件夹下。

复制模板内容

这里文件夹对应的内容如下：

  • assets: 资源文件，主题需要使用的资源会放置到这里。比如头像，主页头像下方的那几个个人账号链接的图标
    • 需要注意的是还有一个static文件夹也是用于存储一些不变资源。这里要注意区分。
  • config: 配置文件，根目录下没有config文件夹，但是 hugo 可能扫描到这里的配置。其中的 hugo.toml（26年版本） 文件请放到根目录。
  • content: 资源文件，存放文章资源和一些比较重要的格式的资源。包括主页侧边栏，个人页面，归档文字等等。

复制过来的 hugo.toml 请删除 以下配置：

1
2

[[module.imports]]
    path = "github.com/CaiJimmy/hugo-theme-stack/v3"

并确保 根目录和 config 文件夹中只有一个 hugo.toml 文件。

这些完成后，再次运行 hugo server，应该就能在网页上看到该主题 的完整内容了。

你可以在 content/post中管理文章。建议每篇文章都创建一个文件夹保存，方便管理（可以将该文章需要使用的图片等内容一并打包到该文件夹下）。 hugo 可以识别多级的文件夹：

这里的 article-name.zh.md 的中间的 zh 表示其为中文简体。这和 网站语言有关。当网站切换语言的时候，访客看到的就是不同的文章。比如在日语环境下，访客看到的就是 article-anme.ja.md 的内容。

自定义

你可以自定义项目的大部分内容。详细自定义内容见官方文档。这里主要说明几个比较复杂的自定义选项。

评论功能

见 stack 主题文档。这里以utterances为例子，你在本地只需要增加一个如下的配置：

1
2
3

[comments]
  enabled = true
  provider = "utterances"

之后，你需要在你配置好的远程的github仓库中安装一个utterances，安装好后再根据你的需求配置 comments.utterances

1
2
3
4

# 这里是远程仓库安装好后配置的。
  [comments.utterances]
    repo = "yourAccount/yourRepo"  # 尝试改为完整格式 "用户名/仓库名"
    issueTerm = "pathname"
    label = "Comment"

粒子背景

你可以下载一些已经写好的内容到static文件中并使用。hugo在构建的时候会完整的保留static文件。

使用 git modules 功能下载 particles.js 到static文件

1

git submodule add https://github.com/VincentGarreau/particles.js/ static/particles.js

然后使用它即可。

需要注意的是，由于 hugo 构建的时候默认是将static文件夹全部保留到 public 文件夹中，但是这里使用 git submodule 功能导致 particles 被标记为了一个 module模块。当你要上传public文件的时候，由于 public 的 git 仓库没有标记对应的子模块（particles 是作为源项目的模块，不是生成的博客项目的模块，这里在之后的部署和推送章节会讲到），因而在上传到 github上后会出现报错。

解决的方法有两个。

第一，配置hugo，可以配置 hugo 构建的时候的对于 static 的过滤模式，防止其中的 .git 和 .gitignore 等和git相关的文件被保留奥到成品即可。

1
2
3
4

[[module.mounts]]
    source = 'static'
    target = 'static'
    excludeFiles = ['particles.js/.gitignore', 'particles.js/.git']

第二，配置生成网页的仓库的 .gitignore（即在 public 文件夹下配置 .gitignore）。原理类似，不要让 网页博客项目的 git 追踪 原本属于 源文件的 git 文件即可。但是要注意，如果删掉public文件，其中的 git 配置也会被一并删掉。

不放心的话，两种方式都可以使用，互不干扰。

本地自动推送更新

要将你生成的网页挂载到网路上，而不是你的本地，你需要先有一个 github 账号。

而后你需要建立两个仓库。一个是管理原文的仓库，一个是管理生成的网页文件的仓库。将对应的内容推送到对应的远程仓库。 而后在网页仓库处配置 page 选项。具体配置方法可查找网络。在那之后你就可以在你的 github对应的仓库页面看到你的静态博客了。

自动推送

网络上大部分人都是推荐在远程的源码仓库配置 GitHub Actions，这里介绍一个纯本地的方法，主要使用的是 git hooks 机制。

首先，在根目录创建一个自动化脚本，其负责在每次将代码提交到源码仓库的之前编译网页，并更新远程网页仓库的内容。

# deploy.ps1
# 功能：编译 Hugo 网站，并将 public 目录内容提交到远程仓库

Write-Host "开始构建 Hugo 网站..." -ForegroundColor Green
hugo --minify

if ($LASTEXITCODE -ne 0) {
    Write-Host "Hugo 构建失败！" -ForegroundColor Red
    exit 1
}

Write-Host "Hugo 构建成功！" -ForegroundColor Green

# 进入 public 目录
Set-Location public

# 检查是否有文件变更
$status = git status --porcelain
if ($status) {
    Write-Host "检测到文件变更，准备提交..." -ForegroundColor Yellow
    git add .
    $date = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    git commit -m "Automated deploy: $date"
    
    Write-Host "推送到远程仓库..." -ForegroundColor Green
    git push origin main
    
    Write-Host "部署完成！" -ForegroundColor Green
} else {
    Write-Host "没有检测到文件变更，无需提交。" -ForegroundColor Yellow
}

# 返回项目根目录
Set-Location ..

#!/bin/sh


echo "检测到 push 操作，开始自动部署..."

# 切换到项目根目录
PROJECT_ROOT="$(git rev-parse --show-toplevel)"
cd "$PROJECT_ROOT" || exit 1

# 注意，这里使用的 power shell，Windows power shell 运行可能会报错
pwsh.exe -ExecutionPolicy Bypass -Command "& '$PROJECT_ROOT/deploy.ps1'"

# 如果部署失败，阻止 push
if [ $? -ne 0 ]; then
    echo "部署失败，终止 push"
    exit 1
fi

echo "部署完成，继续执行 push"
exit 0

这段代码会使得git 在每次 源文件项目提交远程仓库的时候检查并尝试运行上面写好的脚本。

这里的网页仓库只有一条分支，多分支的情况请自行更改内容。

这里配置好了之后，在你每次源码进行 push 操作的时候，git会为你自动提交最新的网页到网页仓库上。

这样做可以避免去处理复杂的云端问题。尽管本地部署局限很多，包括但不限于比不上云端环境稳定，需要很多依赖，多设备情境下的脚本是否会出问题未知，以及更换设备的时候需要重新配置所有环境等等。但是由于我个人平时都是用电脑写作，而且也不频繁更换设备，这种本地自动化推送的方案对我而言就完全够用了。
